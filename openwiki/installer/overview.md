# Installer and package CLI

`packages/codekeeper/src/cli.mjs` and `packages/codekeeper/bin/` expose the `codekeeper` installer and `codekeeper-verify-package` verifier. The installer supports initialization, update, check/preflight, settings, TUI flows, and explicit package selection such as `--current-package`; it reports formatted errors and never treats an unverified package as trusted.

`runCli` coordinates `inspectRepository`, `preflight.mjs`, `plan.mjs`, prompts, `configureRepositorySettings`, `createSetupCommit`, and `pushAndOpenSetupPullRequest`. Preflight and confirmation snapshots are rechecked before settings and Git mutation; drift raises `PREFLIGHT_CHANGED` before mutation. Settings and secrets are applied before generated files are committed, then branch/remote SHA and PR state are checked around push and PR creation. `install.mjs` reports each stage, converts timeout/failure into actionable installer errors, and `rollbackPreCommit` removes only narrowly scoped generated changes; settings, remote pushes, and PRs may require manual resume/reconciliation rather than blind rerun. `plan.mjs` compares the current managed state with the artifact catalog. `updater.mjs` handles release transitions, renamed/retired artifacts, and latest initialization behavior. `settings.mjs`, `settings-tui.mjs`, and `tui.mjs` own installer preferences; these are distinct from runtime policy.

The package CLI's side effects include repository files, Git branches/commits/PRs where explicitly selected, and GitHub variables/secrets. Credential matrix: fresh install requests provider keys for each selected model mode, workspace/Codex keys for each enabled workspace, the tracing key only when tracing is enabled, and the App credential when mutation-capable workflows are selected; release update requests the package receipt plus only secrets newly required by changed modes; configuration-only/settings update requests no unchanged package/App secret and only newly enabled provider/workspace/trace credentials; rerun with unchanged settings requests none. Persistent adopter-owned state includes `.github/codekeeper/agents/*.md` overrides, unrelated repository files, existing Git branches/commits/PRs, GitHub variables/secrets not owned by Codekeeper, and live issue/PR content; only catalogued Codekeeper files and explicitly selected settings are eligible for mutation. Reruns preserve adopter-owned `.github/codekeeper/agents/*.md` overrides, unrelated repository files, and existing release-owned files not changed by the active catalog; package-owned generated callers/configuration are the files eligible for rewrite. Configuration precedence is CLI/TUI selection over existing repository state where the command permits it, while runtime behavior remains governed by `.github/codekeeper.json`; see [configuration](../architecture/configuration.md).

`updater.mjs:runLatestUpdate` resolves an exact semantic version and SHA-512 receipt, runs `npm pack`, verifies tarball identity/bytes/symlinks, installs with scripts disabled, checks the staged CLI entrypoint and dependency graph, and cleans temporary staging on failure. Expected release values are passed through `CODEKEEPER_UPDATE_EXPECTED_*`; a changed same-version tarball, package identity, or registry receipt is rejected.

Focused tests: `install.test.mjs`, `preflight.test.mjs`, `assets-plan.test.mjs`, `settings.test.mjs`, `tui.test.mjs`, `updater.test.mjs`, `pem-input.test.mjs`, and installer trust/package acquisition tests. Run `cd packages/codekeeper && npm run check`.
